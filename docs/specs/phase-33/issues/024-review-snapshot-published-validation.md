# I24: Validate the published two-axis snapshot workflow

## Parent spec or request

`docs/specs/phase-33/004-cli-owned-review-provenance-amendment.md`

## Intent summary

Prove the packed CLI/compiler and generated workflows run both independent
review axes through one local CLI-owned immutable snapshot without weakening
their separation or safety contracts.

## Behavior slice

Install or execute the locally packed artifacts in a temporary real Git
repository, construct one review snapshot, exercise manifest/read/evidence,
run Spec v2 and change-risk v3 workflow fixtures, change the worktree between
rounds, rebuild correctly, verify migration refusals, reach terminal state,
and clean up the store.

## Non-goals

- Adding feature behavior beyond Amendment 004.
- Live hosted reviewers, GitHub dependency, telemetry, source upload, remote
  fetch, or production access.
- Replacing Phase 33 I6; I6 remains independently dispatchable for the
  previously approved published change-risk evaluation.

## Acceptance criteria

- Packed CLI exposes build/manifest/read/evidence/cleanup and packed compiler
  exposes the exact structural contracts.
- One handle supplies complete changed and unchanged-consumer evidence to both
  axes while their results, priorities, contexts, and remediation queues stay
  separate.
- The three preserved Spec attacks and caller-minted change-risk identity are
  rejected through the installed path.
- A changed worktree produces a different handle; an unchanged terminal review
  reuses the same handle according to the existing confirmation rules.
- v1/v2 active review migration is refused and historical records remain
  readable without rewrite.
- Runtime sentinels prove no network, upload, staging, commit, lock, outside-
  root read, symlink dereference, bundle dump, or cleanup escape.
- Corruption, limits, concurrent change, missing refs, binary ranges, gitlinks,
  and every closed error/exit mapping are exercised against packed code.
- Canonical generated artifacts and pack manifests include every new shipped
  file, I14 passes committed bytes/path sets, and `npm run check`, doctor where
  applicable, goldens, and pack verification exit zero.

## Expected RED proof

The locally packed CLI lacks the snapshot command surface and the generated
workflows cannot complete both axes through one handle.

## Expected GREEN proof

The installed end-to-end journey completes locally with deterministic handles,
separate clean results, exact migration refusal, terminal cleanup, and all
safety sentinels green.

## Seam under test

Published integration seam: packed CLI/compiler + generated workflows in a
real temporary repository -> complete local two-axis review journey.

## Allowed mock boundary

Reviewer model responses may use closed sanitized envelopes. Do not mock Git,
filesystem, packed commands, snapshot access, workflow selection, validators,
or artifact guards.

## Test command guidance

Run the focused packed journey, all affected package tests/goldens, doctor,
`npm run check`, `npm run verify:pack`, and I14 by exit code.

## Likely file ownership

- Published-workflow integration tests and sanitized fixtures
- CLI/compiler pack manifests
- Canonical generated workflows and self-applied artifacts
- Phase 33 and user-facing CLI/review documentation

## Dependencies

## Parallelism notes

Final integration only. Do not begin while either axis still has a raw
descriptor/ID path or unreviewed generated bytes.

## Contract impact

No new contract. Supplies release-level proof for Amendment 004.

## Security impact

Proves the local-only threat boundary and negative runtime paths against packed
artifacts rather than source-only tests.

## Documentation impact

Finalize CLI reference, two-axis workflow, migration, cleanup, storage, and
threat-model documentation from observed packaged behavior.

## Implementation context

Use the real pack output; package-source imports are insufficient evidence for
the published seam.

## Review expectations

Build the complete amendment spec-to-test matrix. Treat static-only evidence
as insufficient for IO, no-upload, path-boundary, migration, or package claims.
