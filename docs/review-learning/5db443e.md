## Evidence

### `state-classification|generated-region-ownership|scripts/verify-self-applied-artifacts.mjs|evaluateSelfAppliedArtifacts|incomplete-propagation`

- Raised round 1, still open after round 2's fix, closed in round 3.
- The orphan sweep collected candidate directories from the dirnames of
  currently emitted generated-owned paths. A directory that lost every emitted
  artifact stopped being swept, and the same commit regenerates the lockfile,
  so the retired path was in neither candidate source. Every skill artifact is
  the only file in its directory, so retiring one skill hit this exactly.
- Round 2's fix widened the unit from directory to root and was proven
  insufficient by the same method: disabling a client removes a whole root's
  emissions in one profile edit, so the root stopped being a sweep unit at the
  moment its artifacts were stranded.
- Evidence in both rounds was a direct probe of the exported pure evaluator
  returning `ok: true` for a tree with live orphans checked in, reproduced
  independently by the orchestrator before the finding was accepted.
- Fixed by making the sweep units the frozen `GENERATED_ARTIFACT_ROOTS`
  constant, independent of emission, backstopped by an `unknownRoots` category
  that fails by name when an artifact is emitted into an undeclared root.

### `state-classification|contract-completeness|scripts/verify-self-applied-artifacts.mjs|GENERATED_ARTIFACT_ROOTS|other`

- Raised round 3 as a direct consequence of round 3's own fix: sweeping
  declared roots makes any committed file under them that nothing emits a hard
  gate failure, which is wider than the acceptance criterion's "a
  generated-owned path that is checked in but no longer emitted".
- The widening is not avoidable while the criterion is enforced, because once a
  commit stops emitting a path it also regenerates the lockfile that recorded
  it, so nothing in the tree still attests the path was ever generated-owned.
- Fixed by disclosing it as divergence 5 of the brief, naming the reachable
  consequence (`.claude/commands/*.md` would fail `npm run check`) and the
  narrower fallback if the owner declines, and by removing `.tabnine` from the
  root list so only roots the profile actually emits into are declared.

### `parser-version-contract|parsing-validation|scripts/verify-self-applied-artifacts.mjs|parseOwnershipRefusal|incomplete-propagation`

- The refusal parse matched one compile header and one reason string. Compile
  has three refusal headers, all exiting 3 with the same item shape, and four
  reasons; a mixed refusal named a partial path list and the omitted paths
  looked clean.
- Fixed by keying on the shared `Refusing to ...:` header shape plus the
  `- <path> (<reason>)` item shape and capturing the reason rather than
  matching it. A header-only match yields an empty item list and falls through
  to the throw, so a non-refusal failure is not downgraded into a tidy report.
  CRLF tolerance was added for the same reason: this parses another process's
  stream, not a file.

### `cross-consumer-integration|generated-region-ownership|packages/compiler/src/change-risk-policy.ts|CHANGE_RISK_HIGH_RISK_SURFACES|ownership-violation`

- The guard was declared only under `network-process-execution`, the sole
  membership its own mechanical coverage test forces. It implements ownership
  rather than carrying it, like `regions.ts` and `golden.ts`, so a future
  change widening its exemption list would have routed to a
  network-process-boundary review and never to an ownership one.
- Fixed by dual membership, following the precedent of
  `scripts/verify-pack-files.mjs`. Verified inert: a literal glob, no unrelated
  path reclassified, no emitted artifact or golden fixture moved.

### `state-classification|generated-region-ownership|scripts/verify-self-applied-artifacts.mjs|formatSelfAppliedArtifactReport|other`

- A committed file under a generated root that was never emitted was worded as
  an orphan and told its author to "restore whatever stopped emitting it".
- Fixed by splitting on evidence rather than on a guess. A path the committed
  lockfile still records is `orphaned`; a path nothing records is `unrecorded`,
  and its remediation offers both readings. The reviewer's suggested wording
  ("was never emitted") was deliberately not adopted, because the primary
  retirement case also lands in that class and the stronger claim would be
  false for it. The reviewer accepted the weaker claim as correct on re-review.

### `state-classification|generated-region-ownership|scripts/verify-self-applied-artifacts.mjs|evaluateSelfAppliedArtifacts|missing-validation`

- The `unknownRoots` backstop that keeps the declared root list honest was
  gated on `generated-owned` ownership, so a `mixed` artifact could open a root
  swept in neither direction: passing while emitted, stranding silently once
  retired.
- Fixed by running the check for every emitted artifact regardless of
  ownership, before the declared-local early return.

### `state-classification|generated-region-ownership|scripts/verify-self-applied-artifacts.mjs|DECLARED_LOCAL_ARTIFACTS|incomplete-propagation`

- Raised by the final clean-room confirmation and left open as `follow-up`.
  `.gitignore` names three emitted per-machine artifacts; the frozen exemption
  list names two. `packages/compiler/src/compiler.ts` emits `.codex/hooks.json`
  as soon as any advisory hook role is selected, at which point the guard
  reports it `missing` and prints commit-the-result remediation for a path that
  can never be committed. Fail-closed, latent today, verified not active.
- Deferred rather than fixed: the fix-round budget was exhausted, and the
  finding is a latent defect in a gate that currently passes. Filed as phase-33
  I15 (`issues/015-artifact-guard-local-exemption-derivation.md`) in the
  separate ledger change, so this reviewed change stays the snapshot that was
  confirmed.

### `preview-before-write-ordering|contract-completeness|docs/specs/phase-33/issues/014-self-applied-artifact-drift-guard.md|Implementation divergences (disclosed, owner ratification required)|other`

- Raised by the final clean-room confirmation and left open as `follow-up`. The

## Process observation, not a promotion input

Across rounds 1, 2 and 3 the fix for one round's finding produced the next
round's finding, three times consecutively — matching the pattern already noted
in this repository's recent history. Rounds 1 and 2 both attempted to derive
the orphan-sweep unit from what the compiler currently emits, and both were
blind to the same class of retirement; round 3's fix was correct but widened
the failure contract, which became round 3's own finding.

The mechanism is that each fix was scoped to the reproduction the reviewer
supplied rather than to the property the criterion states. Recorded here as
evidence for I6 and for any later look at fix-round economics. It is not a
promotion input: it is a property of the remediation loop, not a finding
category, and the promotion table keys on canonical categories of validated
findings.
